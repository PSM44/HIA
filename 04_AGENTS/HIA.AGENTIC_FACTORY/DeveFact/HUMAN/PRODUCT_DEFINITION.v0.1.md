==========
PRODUCT_DEFINITION.v0.1
==========

PRODUCT NAME:
DeveFact / DeveFactory / PS.DeveFactory

CANONICAL DEFINITION:
DeveFact is a Development Control System for AI-assisted delivery.

RELATION TO HIA:
DeveFact is initially a module of HIA:
HIA.AGENTIC_FACTORY / DeveFact

It must keep a clear product boundary so it can later become:
- an internal tool for Pablo,
- a tool usable by non-technical users,
- a sellable product,
- or an open-source project.

PURPOSE:
Control, orchestrate, validate and audit AI-assisted delivery.

DeveFact converts ambiguous needs into controlled delivery flows:
idea -> discovery questions -> answers -> task packet -> agent execution -> TOVS -> validation -> registers -> export -> next action.

PRIMARY USER SEQUENCE:
1. Pablo as initial advanced operator.
2. Pablo's wife as future non-technical user.
3. External users as future sellable or open-source audience.

CORE VALUE:
- accelerate development,
- reduce errors,
- control AI execution,
- preserve context,
- document decisions,
- support overnight / asynchronous work,
- generate traceable deliverables.

NOT A COMPLETE PLATFORM YET:
At v0.1, DeveFact is not a finished platform.
It is a controlled product/module evolving through successive functionalities.

EVOLUTION MODEL:
DeveFact advances by adding successive functionalities.
Each functionality demonstrates its operation through one or more controlled use cases.
The roadmap may later culminate in an advanced deployment once the functional base is validated.

FAILURE CONDITION:
The stage fails if it is not understandable or functional in the eyes of management.

SUCCESS METRIC v0.1:
Given a minimal controlled case, DeveFact must create, execute, validate and export a complete run with TOVS evidence, no unauthorized push, no secrets, no loss of context and a management-readable explanation.
