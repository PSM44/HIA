==========
FUNCTIONAL_ROADMAP.v0.1
==========

ROADMAP PRINCIPLE:
DeveFact evolves by functionalities, not by isolated use cases.
Each functionality is demonstrated through controlled use cases.

FUNCTIONALITY F01 - RUN CREATION
Goal: create a controlled run from a raw idea.
Current evidence: DEVF.NEW_RUN.v1.ps1 tested in BATCH-0015.

FUNCTIONALITY F02 - DISCOVERY QUESTIONS
Goal: ask enough questions to clarify what, how, why, user, expected behavior and success criteria.

FUNCTIONALITY F03 - TASK PACKET GENERATION
Goal: produce executable task packets with scope, no-scope, allowed paths, dependencies, acceptance criteria, validation and TOVS expectations.

FUNCTIONALITY F04 - AGENT HANDOFF
Goal: hand work to an AI/tool executor under controlled constraints.

FUNCTIONALITY F05 - TOVS CAPTURE
Goal: collect compact execution evidence for continuity and control.

FUNCTIONALITY F06 - VALIDATION LOOP
Goal: verify outputs before commit or next stage.

FUNCTIONALITY F07 - REGISTER GOVERNANCE
Goal: preserve detailed accumulated history without replacing it with summaries.
Current evidence: BATCH-0017 and BATCH-0018.

FUNCTIONALITY F08 - BLOCKER HANDLING
Goal: park blocked tasks with options A/B/C and expert recommendation.

FUNCTIONALITY F09 - CONTEXT EXPORT
Goal: export context package for migration, audit or another AI instance.
Current evidence: BATCH-0012 and BATCH-0013.

FUNCTIONALITY F10 - MANAGEMENT DEMO LAYER
Goal: produce a management-readable explanation of what happened, what was achieved, what remains and what risks were controlled.

DEPLOY ADVANCED:
Advanced deployment is a later stage.
It should be defined only after the base functionality set is validated.
